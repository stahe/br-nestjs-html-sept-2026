    3. O modelo da ação

    Uma ação precisa de informações enviadas pelo navegador: os parâmetros da URL ([?name=martin&age=42]), os campos de formulário e os parâmetros de rota. O curso original designa todas essas informações como o modelo da ação. Este capítulo mostra como o [NestJS] o fornece à ação, o converte para o tipo correto e o valida.

    import { Controller, DefaultValuePipe, Get, ParseIntPipe, Query } from '@nestjs/common';

@Controller('parameters')
export class ParametersController {
  // /parameters/action01?name=martin
  @Get('action01')
  action01(@Query('name') name: string): string {
    return `name = [${name}], of type ${typeof name}`;
  }

  // /parameters/action02?age=42: um parâmetro é SEMPRE uma string
  @Get('action02')
  action02(@Query('age') age: number): string {
    return `age = [${age}], of type ${typeof age}`;
  }

  // /parameters/action03?age=42: ParseIntPipe converte (ou rejeita)
  @Get('action03')
  action03(@Query('age', ParseIntPipe) age: number): string {
    return `age = [${age}], of type ${typeof age}`;
  }

  // /parameters/action04?page=2: um valor padrão se o parâmetro estiver ausente
  @Get('action04')
  action04(@Query('page', new DefaultValuePipe(1), ParseIntPipe) page: number): string {
    return `page = [${page}], of type ${typeof page}`;
  }

  // /parameters/action05?name=martin&age=42: todos os parâmetros de uma vez
  @Get('action05')
  action05(@Query() parameters: Record<string, string>): object {
    return parameters;
  }
}

    Vamos detalhar este código:

    • Linhas 6–9: [@Query('name')] injeta o valor do parâmetro [name] da URL (a parte que segue [?], chamada de a query string ou [query string]);
    • linhas 12–15: o parâmetro [age] é declarado com o tipo [number]... mas esse tipo é apenas uma declaração [TypeScript], que é removida na compilação. O que recebemos é sempre uma string, como mostra a execução;
    • linhas 18–21: [ParseIntPipe] é um pipe: um objeto que transforma (e valida) o valor de um parâmetro antes que ele chegue à ação. Aqui, a string ['42'] se torna o número 42; uma string não numérica causa um erro 400 (Bad Request), sem que a ação seja executada;
    • linhas 24–27: os pipes são encadeados: [DefaultValuePipe(1)] substitui um parâmetro ausente por 1 e, em seguida, [ParseIntPipe] o converte;
    • linhas 30–33: [@Query()], sem nenhum argumento, injeta um objeto contendo todos os parâmetros da URL.

    3.2. Exemplo 08: Um modelo de ação descrito por uma classe

    Quando uma ação tem vários parâmetros, eles são descritos por uma classe, frequentemente chamada de [DTO] ([Data Transfer Object]).     import { Type } from 'class-transformer';
import { IsEmail, IsIn, IsInt, IsNotEmpty, IsOptional, Length, Max, Min } from 'class-validator';

export class PersonDto {
  @IsNotEmpty({ message: 'the name is required' })
  @Length(2, 20, { message: 'the name must have 2 to 20 characters' })
  name: string;

  @Type(() => Number)
  @IsInt({ message: 'the age must be an integer' })
  @Min(0, { message: 'the age must be positive' })
  @Max(150, { message: 'the age cannot exceed 150' })
  age: number;

  @IsIn(['Mr', 'Mme', 'Melle'], { message: 'unknown title' })
  title: string;

  @IsOptional()
  @IsEmail({}, { message: 'invalid email address' })
  email?: string;
}

    Vamos detalhar este código:

    • linha 1: [@Type] vem da biblioteca [class-transformer], que converte os dados recebidos;
    • linha 2: os decoradores de validação do [class-validator];
    • linhas 5–7: o nome é obrigatório ([@IsNotEmpty]) e deve ter entre 2 e 20 caracteres ([@Length]). Cada decorador aceita uma mensagem de erro personalizada;
    • linhas 9–13: [@Type(() => Number)] exige que a string recebida seja convertida em número antes da validação: um inteiro ([@IsInt]) entre 0 e 150 ([@Min], [@Max]);
    • linhas 15–16: o título deve ser um dos valores de uma lista;
    • linhas 18–20: o endereço de e-mail é opcional ([@IsOptional]); se presente, deve ser válido ([@IsEmail]).

    import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  // validação automática de TODOS os modelos de action descritos por uma classe
  app.useGlobalPipes(
    new ValidationPipe({
      transform: true, // converte as strings recebidas nos tipos declarados
      whitelist: true, // remove os campos não declarados na classe
    }),
  );
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

    import { Controller, Get, Query } from '@nestjs/common';
import { plainToInstance } from 'class-transformer';
import { validate } from 'class-validator';
import { PersonDto } from './person.dto';

@Controller('persons')
export class PersonsController {
  // sem ValidationPipe aqui: a action recebe os parâmetros BRUTOS e
  // decide ela mesma o que fazer com os erros
  @Get('action01')
  async action01(@Query() raw: Record<string, string>): Promise<string> {
    // 1. objeto bruto -> instância de PersonDto (conversões de @Type incluídas)
    const person = plainToInstance(PersonDto, raw);
    // 2. verificação das restrições (@IsNotEmpty, @Min...)
    const errors = await validate(person);
    // 3. uma página HTML nos dois casos: sem erro 400
    if (errors.length === 0) {
      return `<p>Welcome ${person.title} ${person.name} (${person.age} years old)</p>`;
    }
    const items = errors
      .map((e) => `<li>${e.property}: ${Object.values(e.constraints ?? {}).join(', ')}</li>`)
      .join('');
    return `<p>The form contains errors:</p><ul>${items}</ul>`;
  }
}

    Vamos comentar este código:

    • linha 11: a ação recebe os parâmetros brutos: um objeto cujos campos são todos strings;
    • linha 13: [plainToInstance] ([class-transformer]) cria uma instância de [PersonDto] a partir do objeto bruto, aplicando as conversões ([@Type]);
    • linha 15: [validate] ([class-validator]) verifica todas as restrições. Ele retorna um array de erros, que fica vazio se tudo estiver correto. Cada erro indica o campo problemático ([property]) e as mensagens das restrições violadas ([constraints]);
    • linhas 17–18: sem erros — uma página de boas-vindas;
    • linhas 20–23: caso contrário, uma página que lista os erros. Nos dois casos, a resposta é uma página HTML, com código de status 200.

    Essa é a técnica que todos os formulários do estudo de caso usarão (veja o Exemplo 19).

import { ArrayMinSize, IsArray, IsIn } from 'class-validator';

    import { BadRequestException, Injectable, PipeTransform } from '@nestjs/common';

// transforma uma data francesa "23/09/2026" em uma data ISO "2026-09-23"
@Injectable()
export class DateFrPipe implements PipeTransform<string, string> {
  transform(value: string): string {
    const m = /^(\d{2})\/(\d{2})\/(\d{4})$/.exec(value ?? '');
    if (!m) {
      throw new BadRequestException(`[${value}] is not a date in the dd/mm/yyyy format`);
    }
    const [, day, month, year] = m;
    const iso = `${year}-${month}-${day}`;
    // "31/02/2026" tem o formato correto, mas não existe
    if (new Date(`${iso}T00:00:00Z`).toISOString().slice(0, 10) !== iso) {
      throw new BadRequestException(`the date [${value}] does not exist`);
    }
    return iso;
  }
}
    • linhas 4–5: um pipe é uma classe [@Injectable()] que implementa a interface [PipeTransform<input, output>];
    • linha 6: seu método [transform] recebe o valor do parâmetro e retorna o valor transformado, que será recebido pela ação;
    • linhas 7–9: um valor que não tem a forma [dd/mm/yyyy] dispara uma [BadRequestException] (400);
    • linhas 13–15: uma data que está no formato correto, mas não existe (31/02/2026), também é rejeitada: [new Date] a “corrige” para 03/03/2026, o que é detectado.

    import { createParamDecorator, ExecutionContext } from '@nestjs/common';
import { Request } from 'express';

// @Language(): o idioma preferido do navegador, lido do cabeçalho
// "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
export const Language = createParamDecorator((fallback: string | undefined, ctx: ExecutionContext): string => {
  const req = ctx.switchToHttp().getRequest<Request>();
  const header = req.get('accept-language') ?? '';
  const first = header.split(',')[0].trim().slice(0, 2).toLowerCase();
  return first || fallback || 'fr';
});
    • Linha 6: [createParamDecorator] cria um decorador de parâmetro, semelhante a [@Query] ou [@Body]. A função recebe o argumento do decorador ([@Language('fr')]) e o contexto de execução da requisição;
    • linha 7: o contexto dá acesso à requisição do [Express];
    • linhas 8–10: são retornadas as duas primeiras letras do cabeçalho [Accept-Language], que indica os idiomas preferidos do usuário.

    import { Controller, Get, Query } from '@nestjs/common';
import { DateFrPipe } from './date-fr.pipe';
import { Language } from './language.decorator';
import { SearchDto } from './search.dto';

@Controller('examples')
export class ExamplesController {
  // /examples/schedule?day=23/09/2026: um pipe personalizado
  @Get('schedule')
  schedule(@Query('day', DateFrPipe) day: string): string {
    return `schedule for the day [${day}]`;
  }

  // /examples/hello: um decorador de parâmetro personalizado
  @Get('hello')
  hello(@Language('fr') language: string): string {
    return language === 'en' ? 'Hello!' : 'Bonjour !';
  }

  // /examples/search?keyword=nest&admin=true: [admin] não é declarado
  @Get('search')
  search(@Query() search: SearchDto): object {
    return search;
  }
}

    import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(
    new ValidationPipe({
      transform: true,
      whitelist: true, // os campos não declarados são removidos...
      forbidNonWhitelisted: true, // ... ou, com esta opção, rejeitados (400)
    }),
  );
  await app.listen(3000);
  console.log('Server started on http://localhost:3000');
}

bootstrap();

    3.6.4. Conclusão

    O modelo da ação é gerado pelo [NestJS] a partir da requisição: parâmetros de rota ([@Param]), URL ([@Query]), corpo ([@Body]) e cabeçalhos ([@Headers]). Os pipes convertem e validam esses valores. Para uma aplicação HTML, geralmente é preferível validar o modelo você mesmo (exemplo 09), para poder reexibir o formulário. Esse é o tema do próximo capítulo.
