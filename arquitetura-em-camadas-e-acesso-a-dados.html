    9. Arquitetura em camadas e acesso a dados

    Os exemplos anteriores mantinham seus dados na memória. Uma aplicação real os armazena em um banco de dados e é organizada em camadas (veja o diagrama na introdução):

    • a camada web (controllers, views): lê a requisição, chama a camada de negócio e seleciona a view;
    • a camada de negócio: regras de negócio;
    • a camada DAO: consultas ao banco de dados.

    Cada camada conhece apenas a camada imediatamente abaixo dela, e o mínimo possível de detalhes sobre ela: a camada web desconhece o SQL, e a camada de negócio desconhece o HTML. Essa separação torna cada camada mais fácil de entender, testar e evoluir. O Exemplo 28 aplica isso ao gerenciamento de uma lista de pessoas: é, em escala menor, o gerenciamento de médicos e clientes do estudo de caso.

DROP DATABASE IF EXISTS dbpersons;
CREATE DATABASE dbpersons CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE dbpersons;

CREATE TABLE persons (
  id INT NOT NULL AUTO_INCREMENT,
  version INT NOT NULL DEFAULT 1,
  first_name VARCHAR(30) NOT NULL,
  last_name VARCHAR(30) NOT NULL,
  age INT NOT NULL,
  PRIMARY KEY (id),
  -- duas pessoas não podem ter o mesmo nome e sobrenome
  CONSTRAINT unq_persons_first_name_last_name UNIQUE (first_name, last_name)
) ENGINE = InnoDB;

INSERT INTO persons (first_name, last_name, age) VALUES
  ('Marie', 'Pélissier', 42),
  ('Jacques', 'Bromard', 35),
  ('Philippe', 'Jandot', 58);
    • Linha 3: o conjunto de caracteres [utf8mb4] aceita todos os caracteres (acentos, emojis etc.). A collation [utf8mb4_unicode_ci] compara strings sem diferenciar maiúsculas de minúsculas nem acentos: para o MySQL, [pelissier], e [Pélissier] são iguais;

    • linha 14: uma restrição de unicidade nomeada: o banco de dados não admite duas pessoas com o mesmo nome e sobrenome. O nome será usado para identificar o erro.

import { Person } from '../entities/person.entity';

// a conexão com o banco de dados; os valores padrão são os do Laragon
export function databaseConfig(): TypeOrmModuleOptions {
  return {
    type: 'mysql',
    host: process.env.DB_HOST ?? 'localhost',
    port: Number(process.env.DB_PORT ?? 3306),
    username: process.env.DB_USERNAME ?? 'root',
    password: process.env.DB_PASSWORD ?? '',
    database: 'dbpersons',
    entities: [Person],
    // o schema é criado pelo script SQL, nunca modificado pelo TypeORM
    synchronize: false,
    // DB_LOGGING=true: exibe os comandos SQL enviados ao banco de dados
    logging: process.env.DB_LOGGING === 'true',
  };
}

    import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { EntityManager, Not, Repository } from 'typeorm';
import { Person } from '../entities/person.entity';

// a camada de ACESSO A DADOS: consultas, sem regras de negócio
@Injectable()
export class PersonsDao {
  constructor(@InjectRepository(Person) private readonly repository: Repository<Person>) {}

  // dentro de uma transação, devemos passar pelo "manager" da transação
  private repo(manager?: EntityManager): Repository<Person> {
    return manager ? manager.getRepository(Person) : this.repository;
  }

  list(): Promise<Person[]> {
    return this.repository.find({ order: { lastName: 'ASC', firstName: 'ASC' } });
  }

  read(id: number, manager?: EntityManager): Promise<Person | null> {
    return this.repo(manager).findOneBy({ id });
  }

  // OUTRA pessoa (id diferente de [exceptId]) com este nome e sobrenome
  namesake(firstName: string, lastName: string, exceptId: number, manager?: EntityManager): Promise<Person | null> {
    return this.repo(manager).findOneBy({ firstName, lastName, id: Not(exceptId) });
  }

  // INSERT se a pessoa não tem id, UPDATE caso contrário
  save(person: Person, manager?: EntityManager): Promise<Person> {
    return this.repo(manager).save(person);
  }

  async delete(id: number, manager?: EntityManager): Promise<void> {
    await this.repo(manager).delete(id);
  }
}
    • linha 9: o [TypeORM] fornece um repositório ([Repository<Person>]) para cada entidade, capaz de ler e gravar na tabela. [@InjectRepository] o injeta;
    • linhas 12–14: dentro de uma transação, todas as consultas devem passar pelo mesmo objeto [EntityManager], o associado à transação. Cada método aceita, portanto, um [manager] opcional;
    • linhas 16–18: [find] com ordenação: [SELECT ... ORDER BY last_name, first_name];
    • linhas 25–27: uma pessoa com o mesmo nome e sobrenome, diferente de [exceptId] ([Not]): útil para modificar um registro, que não deve entrar em conflito consigo mesmo;
    • linhas 30–32: [save] vira [INSERT] se o objeto não tem identificador e [UPDATE] caso contrário.

    A camada DAO não contém regras: apenas consultas.

    import { Injectable } from '@nestjs/common';
import { DataSource, EntityManager } from 'typeorm';
import { PersonsDao } from '../dao/persons.dao';
import { Person } from '../entities/person.entity';
import { BusinessException } from './business.exception';

export interface PersonData {
  firstName: string;
  lastName: string;
  age: number;
}

// a camada de NEGÓCIO: as regras de negócio, e somente elas
@Injectable()
export class PersonsBusiness {
  constructor(
    private readonly dao: PersonsDao,
    private readonly dataSource: DataSource,
  ) {}

  list(): Promise<Person[]> {
    return this.dao.list();
  }

  async read(id: number): Promise<Person> {
    const person = await this.dao.read(id);
    if (!person) {
      throw new BusinessException('This person does not exist (anymore).');
    }
    return person;
  }

  add(data: PersonData): Promise<Person> {
    return this.transaction(async (manager) => {
      // regra 1: duas pessoas não podem ter o mesmo nome e sobrenome
      if (await this.dao.namesake(data.firstName, data.lastName, 0, manager)) {
        throw new BusinessException('A person already has these first and last names.');
      }
      const person = new Person();
      person.firstName = data.firstName;
      person.lastName = data.lastName;
      person.age = data.age;
      return this.dao.save(person, manager);
    });
  }

  edit(id: number, version: number, data: PersonData): Promise<Person> {
    return this.transaction(async (manager) => {
      const person = await this.dao.read(id, manager);
      if (!person) {
        throw new BusinessException('This person does not exist (anymore).');
      }
      // regra 2: não modificamos um registro modificado nesse meio tempo por outra pessoa
      if (person.version !== version) {
        throw new BusinessException('This record has been modified meanwhile: reload it.');
      }
      if (await this.dao.namesake(data.firstName, data.lastName, id, manager)) {
        throw new BusinessException('A person already has these first and last names.');
      }
      person.firstName = data.firstName;
      person.lastName = data.lastName;
      person.age = data.age;
      return this.dao.save(person, manager);
    });
  }

  async delete(id: number): Promise<Person> {
    const person = await this.read(id);
    await this.dao.delete(id);
    return person;
  }

  // [work] executa dentro de uma transação: COMMIT se tiver sucesso, ROLLBACK
  // se lançar uma exceção. Uma violação da restrição de unicidade (duas
  // inclusões simultâneas, por exemplo) vira uma BusinessException
  private async transaction<R>(work: (manager: EntityManager) => Promise<R>): Promise<R> {
    try {
      return await this.dataSource.transaction(work);
    } catch (e) {
      const sqlError = e as { code?: string; message?: string };
      if (sqlError.code === 'ER_DUP_ENTRY' && sqlError.message?.includes('unq_persons_first_name_last_name')) {
        throw new BusinessException('A person already has these first and last names.');
      }
      throw e;
    }
  }
}

    Vamos analisar este código:

    • linhas 16–19: a camada de negócio usa o DAO e o [DataSource] do [TypeORM] (a conexão com o banco de dados) para abrir transações;
    • linhas 25–31: uma pessoa inexistente é uma [BusinessException];
    • linhas 33–45: inclusão de uma pessoa dentro de uma transação. Regra: não pode haver duas pessoas com o mesmo nome e sobrenome. Isso é verificado antes da operação de gravação, para exibir uma mensagem clara;
    • linhas 47–65: modificação. Regra adicional: o bloqueio otimista (linhas 54–56): o formulário de modificação carrega a versão do registro tal como estava quando o formulário foi aberto. Se ela mudou nesse meio-tempo (outro usuário modificou o mesmo registro), a operação é rejeitada, em vez de sobrescrever silenciosamente o trabalho do usuário;
    • linhas 76–86: [dataSource.transaction(work)] abre uma transação, executa [work], depois a confirma ([COMMIT]) ou a desfaz ([ROLLBACK]) se [work] lançar uma exceção. Linhas 81–82: a verificação prévia de homônimos nem sempre é suficiente: dois usuários podem adicionar a mesma pessoa ao mesmo tempo, e ambos podem passar na verificação. A restrição de unicidade do banco de dados, porém, não admite exceções; o erro do MySQL [ER_DUP_ENTRY], identificado pela restrição, torna-se então a mesma [BusinessException].

    import { Transform, Type } from 'class-transformer';
import { IsInt, IsNotEmpty, Max, MaxLength, Min } from 'class-validator';

const clean = ({ value }: { value: unknown }) => (typeof value === 'string' ? value.trim() : value);

// os campos do formulário e suas restrições (comprimentos = colunas SQL)
export class PersonFormDto {

  @Min(0, { message: 'The age must be positive.' })

    import { Body, Controller, Get, Param, ParseIntPipe, Post, Redirect, Render, Res } from '@nestjs/common';
import { Response } from 'express';
import { BusinessException } from '../business/business.exception';
import { PersonsBusiness } from '../business/persons.business';
import { flash } from './flash';
import { PersonFormDto } from './person-form.dto';
import { validateForm } from './validation';

// a camada WEB: ler a requisição, chamar a camada de negócio, escolher a view
@Controller()
export class PersonsController {
  constructor(private readonly business: PersonsBusiness) {}

  @Get()
  @Redirect('/persons')
  root(): void {}

  @Get('persons')
  @Render('list')
  async list(): Promise<object> {
    return { persons: await this.business.list() };
  }

  @Get('persons/add')
  @Render('form')
  addForm(): object {
    return { title: 'Add a person', action: '/persons/add', values: {}, errors: {} };
  }

  @Post('persons/add')
  async add(@Body() body: Record<string, string>, @Res() res: Response): Promise<void> {
    const view = { title: 'Add a person', action: '/persons/add' };
    const { dto, errors } = await validateForm(PersonFormDto, body);
    if (Object.keys(errors).length > 0) {
      res.render('form', { ...view, values: body, errors, error: 'The form contains errors.' });
      return;
    }
    try {
      const p = await this.business.add(dto);
      flash(res, { type: 'success', text: `${p.firstName} ${p.lastName} has been added.` });
      res.redirect('/persons');
    } catch (e) {
      // uma regra de negócio rejeitou a inclusão: exibimos o formulário novamente
      if (!(e instanceof BusinessException)) throw e;
      res.render('form', { ...view, values: body, errors: {}, error: e.message });
    }
  }

  @Get('persons/:id/edit')
  @Render('form')
  async editForm(@Param('id', ParseIntPipe) id: number): Promise<object> {
    const p = await this.business.read(id);
    return { title: 'Edit a person', action: `/persons/${id}/edit`, values: p, errors: {} };
  }

  @Post('persons/:id/edit')
  async edit(
    @Param('id', ParseIntPipe) id: number,
    @Body() body: Record<string, string>,
    @Res() res: Response,
  ): Promise<void> {
    const view = { title: 'Edit a person', action: `/persons/${id}/edit` };
    const { dto, errors } = await validateForm(PersonFormDto, body);
    if (Object.keys(errors).length > 0) {
      res.render('form', { ...view, values: body, errors, error: 'The form contains errors.' });
      return;
    }
    try {
      const p = await this.business.edit(id, Number(body.version), dto);
      flash(res, { type: 'success', text: `${p.firstName} ${p.lastName} has been modified.` });
      res.redirect('/persons');
    } catch (e) {
      if (!(e instanceof BusinessException)) throw e;
      res.render('form', { ...view, values: body, errors: {}, error: e.message });
    }
  }

  @Post('persons/:id/delete')
  async delete(@Param('id', ParseIntPipe) id: number, @Res() res: Response): Promise<void> {
    try {
      const p = await this.business.delete(id);
      flash(res, { type: 'success', text: `${p.firstName} ${p.lastName} has been deleted.` });
    } catch (e) {
      if (!(e instanceof BusinessException)) throw e;
      // nenhum formulário a reexibir: o erro viaja também como flash
      flash(res, { type: 'danger', text: e.message });
    }
    res.redirect('/persons');
  }
}

    Vamos comentar este código:

    • linha 12: o controller conhece apenas a camada de negócio;
    • linhas 14–16: a raiz do site redireciona para a lista;
    • linhas 18–22: uma action assíncrona: a lista é obtida do banco de dados;
    • linhas 30–47: a inclusão, em três etapas: validação do formulário (erros → a página é recarregada), chamada à camada de negócio (sucesso → mensagem pop-up e redirecionamento), [BusinessException] (→ a página é recarregada com a mensagem na parte inferior). Qualquer outra exceção é relançada ([throw e]): trata-se de uma anomalia, que o filtro de exceção do [NestJS] converterá em um erro 500;

    • linhas 78–89: exclusão. Não há formulário a exibir novamente: os eventuais erros também são incluídos na mensagem flash.
